§1

The shape of the system

Everything the household runs is one Java process talking to one PostgreSQL database on one machine that is never reachable from the internet. The interesting architecture is not in the topology — it is in the permission model that three very different clients share, and in the module boundary that lets a second module land without touching the first.

Forces that set the shape

ForceSourceWhat it rules out
≤ 10 users, ≤ 20 devices, one household, one datasetD-04 D-30Tenancy, sharding, horizontal scale, caches

No outbound internet calls at runtime; no telemetryXC-N-002 SEC-N-002Hosted auth, hosted metrics, product-database lookups
Agents (Claude Code, Codex) are first-class clientsD-14 MCP-F-008Session-cookie-only auth; UI-coupled business logic

The three chains exist because the three clients authenticate differently and must not be able to borrow each other's credentials: a browser cookie is worthless on /api, and a session token is rejected outright on /mcp so an agent never holds a full-grant credential MCP-F-002. Everything below that line is shared.

§2

Architectural decisions

Twelve decisions that the requirements force, with the reasoning made explicit so a later change to a requirement shows which decision it invalidates.

AD-1

A single modular monolith, not services

One Spring Boot deployable holds SSR, REST, MCP and the domain. Spring Modulith verifies package boundaries during Maven tests; the modules communicate in process.

At ten users the cost of a service split is pure overhead, and an in-process MCP server shares the domain calculator with REST for free — which is exactly what the parity test demands.

D-30OPS-N-001MCP-F-003CORE-N-001XC-N-005
AD-2

Opaque database-backed tokens — never JWT

Session tokens and API keys are 256-bit random strings, stored as SHA-256 plus an 8-character lookup prefix, compared in constant time. Every request costs one indexed SELECT.

A signed token would carry grants as claims, and the requirement that a revoked grant fails the very next request would then force a revocation lookup anyway — the same read, with a second, forgeable source of truth on top. So the database is the only source of truth for who may do what.

SEC-F-002SEC-F-003SEC-F-005D-07
AD-3

Permission is computed per request, never cached

One evaluator in core.accounts takes the credential, the module and the required level and returns a verdict. Caching TTL is zero by decision, not by omission.

Consequence: the evaluator must be cheap. Grants are a two-column primary key; the join is users → user_module_grants → modules and is covered by the same query that loads the credential.

SEC-F-004SEC-F-005CORE-F-004
AD-4

The shopping list is computed, never stored

ShoppingListCalculator is a pure function of stock rows and desired rows, working in base units. No table, no cache, no invalidation.

That is what makes REST and MCP byte-identical for the same database, and what makes the four worked examples in the requirements executable as unit tests rather than as documentation.

GRO-F-009MCP-F-003D-16
AD-5

MCP supports grocery queries and additions

MCP exposes three query tools and groceries_add_stock. All adapters call the same grocery query and command contracts; an agent can add an existing product or create a product and its initial stock through the shared quick-add command.

Queries require VIEW. Additions require EDIT, a groceries-scoped READ_WRITE key, and the owner's current EDIT grant. Spring Modulith permits both named interfaces while hiding repositories and implementations. Tool hints describe behavior; the server enforces authorization. This review supersedes the earlier read-only restriction in MCP-N-003 and D-10.

MCP-N-003D-10EXT-001
AD-6

Product identity is a derived natural key

product_key = item-slug/brand-slug|generico/attr1+attr2|none/qty-unit with attributes sorted, unique in the database, alongside a composite unique constraint using NULLS NOT DISTINCT so a missing brand still collides correctly.

Because the key is derived, merging a brand or attribute rewrites keys — so merge is admin-only, transactional, and the one operation allowed to resolve a resulting duplicate by folding stock together.

GRO-F-005GRO-F-013D-15DATA-F-001
AD-7

Convert quantities to the same unit before comparing

Each item measures one kind of quantity: COUNT (units), MASS (grams), or VOLUME (millilitres). Every supported unit has a fixed conversion factor: 1 kg = 1,000 g; 1 l = 1,000 ml. We never convert between kinds, such as grams and millilitres.

For example, two 1 l milk cartons plus one 1.1 l carton contain 3,100 ml. A 4 l target is 4,000 ml, so the shopping list needs 900 ml, displayed as 0.9 l. Fractional packages also work: 0.4 of a 5 kg bag is 2,000 g.

Use Java BigDecimal and PostgreSQL numeric(12,3) for stored quantities, never floating-point double. Keep intermediate arithmetic exact, validate stored scale/range, and round up only when calculating whole packages to buy. Lock an item's quantity kind once a product exists so saved amounts keep their meaning.

D-16GRO-F-002DATA-F-004
AD-8

Current state only; no auditing

The home-app scope excludes audit logs, tool-call history and stock-event histories. Stock changes remain atomic. A current lastPurchasedAt value supports purchase suggestions without retaining a history of actions.

HR7 supersedes CORE-F-013, GRO-F-015 and the earlier action-history scope.
AD-9

Server-rendered web, no SPA, no build pipeline

Thymeleaf + Bootstrap 5, with htmx only where a partial update measurably helps. Every action works as a plain form post with a redirect.

This keeps the browser client free of a JavaScript toolchain and makes the iOS app the only place where DTO contracts must be mirrored — one client to keep in sync with OpenAPI instead of two.

ADM-N-002WEB-N-003IOS-N-002
AD-10

The home screen is data, not code

GET /api/v1/features returns catalogue rows the caller has a grant for — code, title, image URL, permission — and both clients render whatever comes back.

Adding a module is therefore a migration row plus server code; no iOS release is needed for the card to appear.

CORE-F-005CORE-F-012EXT-012
AD-11

The trust chain is part of the product, not the setup

TLS with a household CA means certificate trust fails on someone's phone eventually. So the iOS app detects NSURLErrorServerCertificateUntrusted and shows an install-the-root-CA screen, Caddy renews short-lived leaf certificates automatically and the System page reports renewal failures, and the MCP docs carry the Node and Rust trust-store steps.

Treating trust failures as a supported state rather than an error is what keeps MCP-F-008's ten-minute setup claim honest.

SEC-N-001IOS-F-001OPS-F-004V-04V-09
AD-12

Tests run against real PostgreSQL, always

Testcontainers with the production major version for every repository, service and migration test; no H2. Migration-from-empty and migration-from-previous-release run on every PR.

The schema leans on Postgres-specific behaviour — unaccent, NULLS NOT DISTINCT, jsonb, partial indexes — so an in-memory substitute would test a different system.

How Spring Modulith recognizes this structure

Set spring.modulith.detection-strategy=explicitly-annotated in src/test/resources/spring-modulith.properties. Annotate the eight module packages above with @ApplicationModule; leave controllers and core unannotated. Otherwise default direct-subpackage discovery would collapse all core domains into one module. Keep module roots free of implementations and expose only the listed contract packages with @NamedInterface.

// core/groceries/package-info.java
@org.springframework.modulith.ApplicationModule(
    id = "groceries", allowedDependencies = {"shared", "shared :: images"})
package com.homeserver.core.groceries;

// core/groceries/command/package-info.java
@org.springframework.modulith.NamedInterface("command")
package com.homeserver.core.groceries.command;

// mcp/package-info.java
@org.springframework.modulith.ApplicationModule(id = "mcp", allowedDependencies = {
    "groceries :: query", "groceries :: command", "security :: api", "shared"})
package com.homeserver.mcp;

Query and command contracts carry their own request/result types; clients never need persistence entities. Repository ports may use exported model types. Exporting a model or SPI does not grant every module access: each consumer must also allow it explicitly.

Credential model — what the caller presents

This is the authentication contract for client developers: choose the row for your client to see how it logs in, stores its credential and reaches the server. It belongs here because a cookie, a phone token and an agent key intentionally have different powers; implementation must not infer that every authenticated client can do everything.

Client / credentialIssue, storage and lifetimeAllowed surfaces
Browser / web session cookieForm login; opaque container session ID; server memory, 24 h idle, lost on restart. Secure, HttpOnly, SameSite cookie; CSRF for writes./app; /admin only for ADMIN. Only this client creates API keys.
iPhone / hs_sess_ tokenAPI login; Keychain on device; 90 d sliding lifetime./api/v1; current user grants. ADMIN implies EDIT for module operations, never access to admin endpoints.
Agent / hs_key_ API keyCreated in web UI, secret shown once; default 365 d, custom expiry or never. Owner/admin can revoke./mcp and module REST operations; explicitly scoped modules and READ / READ_WRITE cap. Never admin endpoints or key creation.

Both bearer types use 256 random bits from SecureRandom, base64url encoding, SHA-256 hashes and an indexed 8-character lookup prefix; compare candidate hashes in constant time. Store only metadata and hashes server-side, never retrievable secrets. The prefix is a lookup aid, not proof of identity. A local parameterized query joins credentials to current accounts, grants and enabled modules on every request; no remote introspection or permission cache.

Effective permission — what this request may do

After validating the credential, account state and password-change gate, apply the rows below. Read VIEW < EDIT as an ordered scale; “lower” means a key can restrict its owner but cannot gain privileges. This is the shared authorization contract for web, phone and tools, and the source for table-driven tests.

ConditionResult
Module disabled, credential expired/revoked, or account not approvedDeny before business logic (see gate order below).
Web session or phone tokenUser's module grant (none / VIEW / EDIT); ADMIN implies EDIT for enabled modules.
API keyModule must be in key scope. Lower of explicit owner grant and key cap: READ → VIEW, READ_WRITE → EDIT. ADMIN does not replace the explicit owner grant for keys.

Example: an EDIT owner with a READ key can list stock but cannot add milk. A READ_WRITE key also loses write access on the next request if the owner's grant becomes VIEW. Standing risk — a leaked API key

A key is a bearer credential sitting in a shell environment on a laptop. Three properties contain it: it can never exceed its owner's live grants, it cannot touch /admin/**, and write tools require both READ_WRITE scope and the owner's EDIT grant. A leaked write-capable key can read grocery data and add stock or products, revocable in one click from either the owner's page or the admin overview, with last_used_at as the detection signal.

§5

Groceries domain

The module exists to answer one question correctly. Everything in the model is there because the diff needs it.

Identity and quantity

A Product is Item × Brand? × Attribute-set × Package(qty, unit). Attributes are a global vocabulary — deslactosada created on a milk is immediately available on a yoghurt and filterable across both. Brand absent means genérico, modelled as brand_id IS NULL, never as a row.

product_key  = item-slug / brand-slug|generico / attr1+attr2|none / qty-unit
variant_key  = sorted attribute slugs joined with "+"   ("" when none)
display_name = "Leche Alpina deslactosada 1 l"          derived, never user-entered

item total   = Σ over products of  packages × package_qty × unit.to_base_factor
needed       = max(0, target_base − current_base)       both in the item's base unit
packagesToBuy = ceil(needed / package_size_in_base)

Suggestion order

  1. The preferred brand's product with the largest package ≤ needed; otherwise that brand's smallest package.
  2. Otherwise the item's most recently purchased product, using the current stock row's lastPurchasedAt value.
  3. Otherwise any active product. If none exists: noProductKnown, and the row still appears so the household knows to buy it.

Tool annotations: where the hints live

Hints are metadata in each tool's annotations object returned by tools/list. Set them in the server-side MCP tool registration (the SDK tool schema), alongside name, description, inputSchema and outputSchema. They are not input arguments, HTTP headers, database fields or authorization rules. A client may use them when presenting a tool or asking for approval, but the server must enforce permissions independently.

  "name": "groceries_add_stock",
  "annotations": {
    "readOnlyHint": false, "destructiveHint": false,
    "idempotentHint": false, "openWorldHint": false

Transport statelessness does not make writes idempotent. With request_id, deduplicate for 24 h using the authenticated credential, operation and ID; persist a payload hash and result in the same PostgreSQL transaction as the stock change. A reused ID with changed arguments is a conflict. Without an ID, do not automatically retry a timed-out write: inspect stock first. Keep the tool hint false because the ID is optional. The short-lived deduplication record is operational state, not an action history.

Use Spring AI's WebMVC MCP starter with spring.ai.mcp.server.protocol=STATELESS and spring.ai.mcp.server.stateless.mcp-endpoint=/mcp. No MCP session ID, affinity or conversational state; web login sessions and durable credential rows remain separate. No server-initiated sampling, elicitation or other requests to clients. Sources: Spring AI stateless transport, MCP annotation semantics.

For the current 2026-07-28 protocol, implement server/discover, send protocol version and client capabilities in each request's _meta, include required Mcp-Method/Mcp-Name headers where applicable, and return resultType. There is no initialize handshake. Tool listings include the revision's cache metadata; select private caching with zero freshness for this application. Earlier client compatibility, if supported by the chosen SDK, uses that earlier revision's handshake and envelope. request_id is our stable write-deduplication argument, distinct from the JSON-RPC request ID. These wire details require SDK/client contract tests; setting Spring's STATELESS property alone does not prove support for the latest revision. Protocol changes.

Boundaries that keep MCP from hurting the rest

  • Bounded concurrency — at most 4 in-flight tool calls per key, so a slow agent cannot starve the web app MCP-N-002.
  • Domain errors are results, not 500s — isError: true with an actionable message (“attribute 'deslactosado' not found; did you mean 'deslactosada'?”). Only auth and rate limiting are HTTP-level MCP-F-007.
  • Size ceiling — default results under ~8,000 tokens, with limit/cursor on the stock tool; the reference dataset at limit=200 must stay under 30 KB MCP-N-004.
  • No OAuth surface — the well-known discovery endpoints return 404 and WWW-Authenticate carries no resource_metadata, so a client with a static header fails cleanly instead of wandering into a discovery flow MCP-F-002.

Invariants pushed into the schema

  • UNIQUE (product_key) and UNIQUE NULLS NOT DISTINCT (item_id, brand_id, variant_key, package_qty, unit_code) — the second catches a duplicate even when brand is null, which a plain unique index would let through.
  • CHECK (packages >= 0), CHECK (package_qty > 0), CHECK (target_qty > 0).
  • name_normalized = lower(unaccent(trim(name))), unique per catalogue table, maintained by the service and guaranteed by the index even under concurrent creation.
  • Unit-dimension consistency is enforced in the service and covered by an integration test; a trigger is optional.
  • timestamptz everywhere, database and application in UTC; the display zone (America/Bogota) is configuration, returned to iOS in /me.server.tz.

Local DNS and HTTPS setup — V-04 / V-06

Use https://home-companion.home.arpa for every client. The household administrator creates this local DNS record in Pi-hole on the Raspberry Pi, pointing to the active Caddy host's LAN address. With router configuration unavailable, manually set each laptop's network DNS and each iPhone's household Wi-Fi DNS to the Pi's address. Give the Pi a stable LAN address that does not conflict with the router's DHCP allocations; do not enable a second DHCP server. Router changes are not required for Caddy or its internal CA.

home.arpa is reserved for home networks; .local is reserved for multicast DNS. Private DNS, VPNs or guest Wi-Fi that bypass the household resolver must allow this name and LAN access. DNS queries go directly from the client's OS resolver to Pi-hole; after resolution, HTTPS requests go to Caddy. Caddy does not configure client DNS or install client trust.

These are deployment requirements, not evidence of an installed stack. Caddy is the application HTTPS entry point: bind 443 and the redirect on 80 to the Pi LAN interface. Pi-hole separately publishes DNS on UDP/TCP 53; keep its administrative UI off Caddy's ports. App port 8080, PostgreSQL 5432, management and Caddy's administrative API stay private. Trust forwarded headers only from Caddy so Spring issues Secure cookies correctly.

# Caddyfile — application paths share one origin
home-companion.home.arpa {
    tls internal
    @management path /actuator /actuator/*
    respond @management 404
    reverse_proxy app:8080
}
# Compose publishes LAN_IP:443:443 and LAN_IP:80:80 on proxy only.

A certificate's SAN (Subject Alternative Name) is its list of valid hostnames or IP addresses. Caddy issues the leaf certificate for our DNS name and renews it automatically using its internal CA; use its short-lived defaults. The host's IP can change without changing the certificate when DNS is updated. Persist caddy_data: losing its CA requires trusting a new root on every client. Keep CA private keys on the server and distribute only the public root certificate after checking its fingerprint through a trusted local channel.

Install the public root in the laptop's operating-system trust store (and a separate browser store if applicable). On iPhone, install the certificate profile, then enable it under Settings → General → About → Certificate Trust Settings. Swift uses normal URLSession trust evaluation, never “accept all certificates”; request Local Network permission with a clear usage description. A refused LAN permission, unresolved DNS name and untrusted certificate need distinct connection messages. Routine leaf renewal keeps the same root and requires no phone reinstall.

Sources: Pi-hole Docker storage and ports, manual client DNS setup, home.arpa, Caddy automatic local HTTPS, internal CA configuration, iPhone root trust.

Agent connection and certificate trust — V-02 / V-09

The API key proves permission; the CA certificate proves the server's identity. Both are required. Create a groceries-scoped key in the web UI, choose READ for queries or READ_WRITE for additions, and store the secret in the local process environment as HOME_COMPANION_API_KEY. Never commit the value. Use the following templates for local CLI processes on the household network.

// Claude Code: .mcp.json (configuration template)
{
  "mcpServers": {
    "home-companion": {
      "type": "http",
      "url": "https://home-companion.home.arpa/mcp",
      "headers": {"Authorization": "Bearer ${HOME_COMPANION_API_KEY}"}
    }
  }
}
# Before starting the local Claude Code process:
export NODE_EXTRA_CA_CERTS="/absolute/path/household-root-ca.pem"

[mcp_servers.home_companion]

export CODEX_CA_CERTIFICATE="/absolute/path/household-root-ca.pem"
# SSL_CERT_FILE is Codex's fallback when CODEX_CA_CERTIFICATE is unset.

Restart the client after setting its environment and ensure the launcher actually inherits the key and CA path; a GUI or background supervisor may not inherit terminal exports. Codex and Claude have different trust-loading mechanisms, so Node's variable is not a universal Rust-client setting. Keep certificate verification enabled.

Check in order: (1) the DNS name resolves to the active host; (2) curl --cacert /absolute/path/household-root-ca.pem https://home-companion.home.arpa/app completes TLS, even if the application redirects to login; (3) the agent lists four tools; (4) a READ key can query and is denied an addition; (5) a READ_WRITE key with owner EDIT adds one test product; (6) revocation denies the next call. A TLS error happens before HTTP authentication; a 401 points to credentials, and a 403 to account/grant/scope checks. These are release acceptance steps, not tests already executed.

Client references: Claude MCP configuration, Claude custom CA trust, Codex HTTP bearer configuration, Codex certificate environment variables.

Host and image baseline — V-10

Raspberry Pi 5 with 16 GB RAM and a 64-bit OS is the deployment baseline. Build and smoke-test a linux/arm64 image; also publish linux/amd64 for Intel Mac hosting. Apple Silicon Macs use the ARM64 image through Docker. Keep volumes on the active host; running the same image on a Mac does not copy the Pi's database. Move the local DNS record when deliberately switching hosts. A future Raspberry Pi 6 is a later hardware migration requiring compatibility and performance checks.

Operational posture

  • Network — 80/443 bound to the LAN interface, 80 redirecting only; no UPnP, no port forwarding; an external scan is part of the release matrix.
  • Names — Pi-hole on the Raspberry Pi maps home-companion.home.arpa to the active Caddy host LAN address. Each client manually selects Pi DNS while router settings are unavailable. Browser, iOS and agents use the same HTTPS name. Router DHCP may advertise Pi DNS later when configuration is available.
  • Secrets — environment variables or Docker secrets only; the repository carries .env.example; startup redacts any variable whose name contains PASSWORD, SECRET, KEY or TOKEN.
  • Logs — JSON to stdout with traceId, userId, credentialType, source, status and duration; json-file driver, 50 MB × 5.
  • Actuator — health without details on the internal port for the healthcheck; details, info and metrics only with an ADMIN web session; everything else disabled.
  • Release — tag → CI builds and pushes the image → docker compose pull && up -d → Flyway migrates on start → smoke checklist: login, stock page, one MCP query and one authorized test addition. Image rollback requires a schema compatible with the previous application version.
The one-way door in this stack

Use backward-compatible schema changes (add column → deploy → backfill → constrain) while the application is in this home scope. An image rollback does not reverse a destructive data migration. No automated recovery system is part of the current architecture.

Localization

The UI is Spanish with es-CO formats — 1,5 l, 2.500 g — and every string lives in messages_es.properties or the iOS String Catalog, with a lint rule failing the build on literals in templates. The API stays locale-neutral and returns plain decimals; formatting is a presentation concern on both clients. Item and brand names are user text and belong to no language, which is why English is a resource-file addition rather than a schema change.

WCAG 2.2 AA basics on web and admin: labelled controls, visible focus, keyboard-operable dialogs, 4.5:1 contrast, and no status conveyed by colour alone.
